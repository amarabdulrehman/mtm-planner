How it works

One message pack, three steps.

A small model only reads the messages. Plain code does every calculation and check, so the figures are exact and each one points back to the message it came from.

What it guarantees

Built to stay correct when the messages change.

Same command for every message

npm run plan -- messages.txt for the first run and for every update. No flags.

Updates are small

A new message uses at most 5 model calls and usually 1. Areas with nothing new make no calls.

Wrong messages are caught

A sender without authority, an out-of-date price, or a change that leaves people without food is rejected with a plain reason.

Everything is on the record

Every model call is numbered with its model, area, input, output and tokens. Download the plan and full trace as one file.

No facts in the code

Every figure comes from the message file, so a pack it has never seen works without changes.

Replies drafted, never sent

Each sender gets a draft reply on the channel they used. A person always presses send.
